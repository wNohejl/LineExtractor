XLINESXLines

A multi-source sports-data ingestion and analytics operations platform.

Version 1.0.0. A desk you run on your own machine, in Docker, on your own free key. Built with .NET 10, Blazor (Interactive Server), MudBlazor 9 and PostgreSQL 17.

XLines does not place wagers and does not integrate with any wagering system.

What XLines is

XLines ingests sports statistics and betting-market data from multiple external providers on a schedule, stores line movement as partitioned time-series, computes performance analytics (closing-line value, ROI, bankroll), and monitors its own ingestion health with operational KPIs, alerting, and an incident log with written root-cause analyses.

The journal records bets placed elsewhere so their performance can be analysed against stored market data. There is no bet-placement path anywhere in the codebase.

Why it exists

Most side projects demonstrate that you can build a feature. This one is built to demonstrate that you can operate one: the interesting part is not the odds, it is the layer that notices when a feed silently breaks at 3am and produces a written RCA afterwards.

XLines is the product; XLines is the platform it is built on. Every project, path, image and command in the repository still says XLines. The two names mean the same desk.

What it does

Ingestion

  • Odds and stats adapters behind two interfaces, so adding a provider is a registration change, not a code change.
  • Three integration styles: synchronous REST pulls, a scheduled bulk slate ingest, and post-final settlement processing.
  • Resilience per source: retry with jittered backoff, circuit breaking, per-attempt timeouts.
  • A budget guard that refuses a run rather than overrun a provider's free-tier ceiling.
  • Store-on-change: a price that has not moved is not written, so every stored row is a real line move.

Analytics

  • Closing-line value: each journal entry is joined to the last price observed before the start.
  • Value at close: the price taken, valued against a fair close, which is the closing market's probability with the book's margin taken out.
  • ROI, win rate against the break-even rate implied by price, a bankroll curve, and breakdowns by market and book.
  • Automatic grading for moneyline, spread and total, including the push cases.

The desk

  • Windows on one screen rather than a set of pages, so source health, the incident and the runs behind it can be read together.
  • Always one horizontal row of full-height columns. Each new window appends and the others give up the space.
  • The limit is the number of columns, not of windows: past it, a window opens as a tab and nothing closes.
  • Workspaces: named layouts stored as fractions of the desk, so one saved on a monitor still fits a laptop.
  • Each window's title bar and taskbar chip carry a live pulse of that window's own state.

Operations

  • KPIs: freshness, success rate, volume-vs-median anomaly detection, and budget burn.
  • An alert engine that opens, updates and auto-resolves alerts, one per rule and source.
  • An incident log that cannot be closed without a root cause and a corrective action.
  • Failure injection, so the detect, alert, incident and RCA loop can be drilled on demand instead of waiting for a real outage.

Quick start

Clone, run setup, start Docker, enter your free key in the desk: fixtures and prices appear. About ten minutes, most of it the first image build. The default runs on The Odds API alone; ESPN is an optional extra you can turn on for box scores and player stats.

You need

  • Gitto clone
  • Docker Desktopor Docker Engine with Compose v2, running. Postgres and the desk run in containers.
  • .NET 10 SDKsetup.ps1 uses it to make the HTTPS development certificate.
  • PowerShellBuilt into Windows. On macOS or Linux, install pwsh and run the same scripts.
  • A free key from The Odds APIThe default source: fixtures (free), prices and final scores (credits), 500 credits a month.

  1. Clone, on the development branch

    main is the stable branch and trails it; the steps are written for LineX_Development.

    git clone -b LineX_Development <repository address> XLines
    cd XLines

  2. Generate the local secrets, and decide about ESPN

    Writes .env (a random database password and certificate password; gitignored) and exports the HTTPS development certificate. Safe to run again.

    .\scripts\setup.ps1

    It asks one question first: whether to turn ESPN on. You do not need it. The answer defaults to No. If Windows says running scripts is disabled, bypass the policy for that one run rather than changing the machine's: powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1.

  3. Get your own free key

    Fixtures, prices and final scores come from The Odds API. Sign up for the free Starter plan at the-odds-api.com; the key arrives by email. Not odds-api.io, which is a different provider with a near-identical name and its own keys.

    Start the desk (next step), open Ops → Odds feeds, paste the key into The Odds API key and press Check and save. The desk asks the provider whether the key is good before keeping it, and keeps it encrypted on your machine, outside the database.

  4. Start it

    docker compose -f docker-compose.yml -f compose/dev.yml up -d --build

    Open https://localhost:9443. The browser warns about the certificate until you trust it (dotnet dev-certs https --trust, your call: it changes the machine's trust store).

Filling the database, pulling prices and scores, and what to do when something does not appear are in the repository's README.

Whose data it is

XLines is a personal tool. It runs on your machine, pulls with your own key, and stores what it pulls in your own Docker Postgres. Nothing is sent to the project or to anyone else.

  • The Odds API. You sign up yourself and use your own key. Its terms allow storing its data and showing it in an application; they do not allow passing the raw data on as a data product, so do not publish a database or dump that holds it. The repository carries none: what your desk holds, it pulled itself.
  • ESPN is optional and off by default. Its endpoints are unofficial and undocumented, read only so that an individual can keep games, scores and box scores in their own local database. ESPN's terms of use license its services for personal, non-commercial use and prohibit automated access; whether to turn it on is your decision. Do not host a desk that shows ESPN-derived data to other people, do not use it commercially, and do not redistribute it.
  • MLB Stats API. MLB Advanced Media permits individual, non-commercial, non-bulk use only. It is off whenever ESPN is.

XLines is not affiliated with or endorsed by ESPN, Disney, MLB, The Odds API or any sportsbook. It takes no bets and is not betting advice. If you gamble, do it legally where you are, at the legal age, and within your means.
